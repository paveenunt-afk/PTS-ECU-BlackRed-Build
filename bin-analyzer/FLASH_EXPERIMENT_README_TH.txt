PTS BIN & Flash 2.0 — รุ่นพัฒนาทดลอง ยังไม่ผ่านการทดสอบกับกล่องจริง

เปิดโปรแกรม
แตก ZIP ทั้งหมด ติดตั้ง Python 3 พร้อม Tcl/Tk แล้วเปิด START_WINDOWS.bat
นี่เป็นซอร์สโปรแกรม Python ไม่ใช่ Windows EXE

ส่วนตรวจไฟล์
เปิด BIN ทุกไฟล์ในชุด 61 ไฟล์ได้ พร้อม HEX, ค้นหา, เปรียบเทียบ และบันทึกสำเนา
เลือกจากปุ่มคลัง BIN ซึ่งแสดงโฟลเดอร์และขนาด ค้นหาชื่อรุ่นได้
อ่าน BIN อื่นได้ 1 byte ถึง 64 MiB แต่ไม่สามารถสรุปว่าแฟลชได้
ไฟล์ XDF 6 ไฟล์และ Fsd 1 ไฟล์เก็บไว้ตามเดิม ไม่ได้ใช้เป็นคำสั่งแฟลช
รายงาน ROM_INDEX.json แสดง SHA-256 และชื่อจากไฟล์ต้นฉบับ
ชื่อโฟลเดอร์ไม่ได้ยืนยันว่าเป็นไฟล์เดิมโรงงานทุกไฟล์

ส่วนดูด–อัดทดลอง
รองรับในโค้ดเฉพาะ Honda 38770-MEN-E21 ขนาด 262144 bytes checksum 0x1FFFA
อ้างอิงโปรเจกต์ HondaECU ของ roccofz1 ซึ่งระบุ CRF450R 2009
แม้โฟลเดอร์ผู้ใช้ระบุ 2009–2012 ก็ไม่ได้หมายความว่าทุกรุ่นปีรองรับ
ใช้ FTDI USB-to-serial ที่มีวงจรแปลงเป็น K-Line เท่านั้น
ไม่ใช่การต่อ TTL ของ FT232RL เข้าขา ECU โดยตรง
ยังไม่มี pinout ที่ยืนยันสำหรับกล่องผู้ใช้ และไม่รองรับ Openport/CAN
ต้องติดตั้ง pylibftdi ตาม requirements.txt และ native libftdi/libusb ให้ตรงกับ Python
DLL และไดรเวอร์ไม่ได้รวมมา โปรแกรมไม่ติดตั้งหรือสลับไดรเวอร์ให้
โปรเจกต์ต้นทางระบุ libusbK บน Windows จึงอาจใช้ร่วมกับ COM driver เดิมไม่ได้

ลำดับการอ่าน
เปิดไฟเลี้ยงกล่อง เลือกปุ่มอ่าน/เขียน ECU แล้วกดดูด ROM ตั้งชื่อใหม่
โปรแกรมตรวจว่าพบ FTDI เพียงตัวเดียว จากนั้น init และส่งคำสั่งอ่าน
อ่านเป็นไฟล์ใหม่เท่านั้น หากขาดช่วงไฟล์ที่เหลือไม่ถือว่าสำรองสมบูรณ์
ถือว่าอ่านครบเมื่อได้ 262144 bytes และผ่าน checksum

ลำดับการเขียน
เปิด BIN เป้าหมายที่ถูกต้องสำหรับ MEN-E21 แล้วกดอัด BIN ที่เปิดอยู่
ตรวจขนาดและ checksum ก่อน แล้วอ่านสำรองกล่องไปยังชื่อใหม่
จะเริ่มลบเฉพาะเมื่อข้อมูลสำรองตรง MEN-E21 อ้างอิงที่แนบมาทุกไบต์
ดังนั้นกล่องที่จูนแล้วหรือ ROM revision อื่นจะถูกปฏิเสธก่อนลบ
ส่งคำสั่งเขียนตาม upstream แล้วอ่านกลับเทียบทุกไบต์
หากอ่านกลับไม่ได้หรือไม่ตรง จะรายงานไม่ยืนยัน/ไม่ผ่าน ไม่รายงานสำเร็จ
หลังเริ่มลบแล้วความผิดพลาดอาจทำให้กล่องต้องกู้คืนด้วยอุปกรณ์อื่น
รักษาไฟเลี้ยงและสายเชื่อมต่อตลอดการทำงาน
บันทึกรายการอยู่ใน logs ข้างโปรแกรม
ไม่มีการกู้คืนอัตโนมัติ และไม่มีการแก้ checksum ให้อัตโนมัติ

ข้อจำกัดที่ต้องทราบ
การทดสอบนี้ครอบคลุมการอ่านไฟล์จริงทั้ง 61 ไฟล์และตรรกะกับอุปกรณ์จำลอง
ยังไม่ได้ทดสอบ GUI บน Windows, ไดรเวอร์ FTDI, timing หรือการลบ/เขียนกับกล่องจริง
โค้ดต้นทางยังไม่มีเอกสาร ACK status ครบ จึงยังไม่ใช่เครื่องมือที่ยืนยันพร้อมใช้กับรถ
รุ่นอื่นในชุดยังไม่รองรับดูด–อัด ไม่เดาโปรโตคอลจากขนาดหรือชื่อไฟล์
